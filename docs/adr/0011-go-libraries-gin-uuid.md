# Go libraries: pgx, franz-go, Gin, and google/uuid

This record replaces [ADR-0008](0008-go-libraries.md). Its Postgres and Kafka choices stand
unchanged; what changes is HTTP, which moves from the standard library to Gin, and order IDs,
which the service now generates (see [ADR-0012](0012-hexagonal-layout-per-service.md)).

| Concern | Library | Pinned |
|---|---|---|
| Postgres driver and pool | `jackc/pgx/v5` (`pgxpool`, `pgx.Tx`) | v5.11.0 |
| Kafka client | `twmb/franz-go` | added in Step 3, where its producer settings are a checkpoint |
| HTTP routing, middleware, request binding | `gin-gonic/gin`, with its binding package and `go-playground/validator` | when first added, Step 2b (#8) |
| Order IDs | `google/uuid` (`NewV7`) | v1.6.0 |
| Logging, config, shutdown | standard library (`log/slog`, `os`, `os/signal`) | — |

pgx and franz-go are chosen for what they expose: SQLSTATE codes (a unique violation from a
dedupe insert, a check violation from overselling, a serialization failure), explicit
transaction control, and producer and consumer settings written as Go code. Those reasons
from ADR-0008 are unchanged.

## Gin

Gin is used for its router, middleware chain, and request binding. Binding splits
validation in two:

- **Request shape** is declared on the handler's DTO with `binding` tags (`required`, `uuid`,
  `gt=0`, `min=1`, `dive`). A tag failure is a 422 listing every invalid field.
- **Business rules** that tags can't express, such as no SKU listed twice, live in the domain
  constructor and return a typed error, also a 422.

A body that isn't a well-formed request at all (bad JSON, a wrong type, an unknown field,
trailing data, a missing `Idempotency-Key`) is a 400. One function in the handler package
maps every error to an RFC 9457 `application/problem+json` response
([ADR-0010](0010-http-idempotency-post-orders.md)).

Setup, done in each HTTP service's router constructor and `main`:

- `gin.New()` with `gin.Recovery()` and a small `slog` request-log middleware. Gin's default
  logger writes its own format to stdout, apart from the service's structured logs.
- `GIN_MODE` is read through the service's `LoadConfig` like every other variable (default
  `release`; the Makefile's `run-*` targets set `debug`).
- `binding.EnableDecoderDisallowUnknownFields = true`, set once in `main`. Rejecting unknown
  fields is what ADR-0010's replay comparison depends on: a field the server ignores is a
  field that comparison can't see. It is a package-level variable in Gin, and the **one
  deliberate exception** to "no package-level state" (ADR-0005). It lives in `main`, never
  in `platform` or a service package.

`gin.Engine` is an `http.Handler`, so `platform/httpserver` and graceful shutdown are
unchanged.

## google/uuid

Order IDs are generated by the service ([ADR-0012](0012-hexagonal-layout-per-service.md)),
and Go 1.26's standard library has no UUID package. `uuid.NewV7` produces time-ordered IDs,
monotonic within one process even for IDs made in the same millisecond. `uuid.UUID` is a
`[16]byte`, which pgx writes as a Postgres `uuid` directly.

Outbox event IDs are **not** generated with it. They stay `DEFAULT uuidv7()` in Postgres,
because the relay orders events by that ID (invariant 8) and one clock, the database
server's, can't skew against itself the way several service instances' clocks can.

## Considered options

- **Keep the standard library for HTTP** (ADR-0008). Go 1.22's `ServeMux` matches methods
  and path patterns, and hand-written decoding is about as short as binding tags. Rejected
  by preference: the project adopts Gin's binding and middleware model, which is the common
  shape of Go HTTP services.
- **Gin as a router only, with hand-written validation.** Rejected: binding is most of what
  Gin adds over `ServeMux`.
- **Echo or chi.** Similar capabilities; Gin was chosen as the most widely used.
- **`gofrs/uuid/v5`**, or a hand-written UUIDv7. The first is equivalent and less used. The
  second teaches the bit layout, but IDs made in the same millisecond need an extra counter
  to stay ordered.
- **Postgres-generated order IDs** (the `uuidv7()` default). Rejected: the service can't
  know an order's ID until after the insert, and tests can't fix it.

## Consequences

- Handlers depend on `*gin.Context`, not `http.ResponseWriter`. Handler tests drive a
  `gin.Engine` with `httptest`.
- Two new direct dependencies (Gin, google/uuid) and Gin's transitive ones, validator among
  them. Any further dependency is still a checkpoint (CLAUDE.md).
- `domain` packages may import `google/uuid` in addition to the standard library
  ([ADR-0012](0012-hexagonal-layout-per-service.md)); it's a value type with no I/O.
- Repository code keeps using pgx types directly, as under ADR-0008.
